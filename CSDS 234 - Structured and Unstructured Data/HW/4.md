## RDF/XML and Schema “Debugging”

You are given an RDF Schema and an RDF/XML data fragment describing a small HealthSense234 dataset.

RDF Schema (in Turtle)

```turtle
- hs:Patient rdfs:subClassOf hs:Person
- hs:Doctor rdfs:subClassOf hs:Clinician
- hs:Clinician rdfs:subClassOf hs:Person
- hs:hasVisit
	- rdfs:domain hs:Patient
	- rdfs:range hs:Visit
- hs:hasAttendingDoctor
	- rdfs:domain hs:Visit
	- rdfs:range hs:Doctor
- hs:livesIn
	- rdfs:domain hs:Person
	- rdfs:range hs:City
```

RDF/XML Fragment
```xml
<rdf:Description rdf:about="hs:Visit1">
	<hs:livesIn rdf:resource="hs:Cleveland"/>
	<hs:hasAttendingDoctor rdf:resource="hs:City1"/>
</rdf:Description>
<rdf:Description rdf:about="hs:Alice">
	<rdf:type rdf:resource="hs:City"/>
	<hs:hasVisit rdf:resource="hs:Visit1"/>
</rdf:Description>
<rdf:Description rdf:about="hs:Bob">
	<rdf:type rdf:resource="hs:Patient"/>
	<hs:hasAttendingDoctor rdf:resource="hs:DrSmith"/>
</rdf:Description>
<rdf:Description rdf:about="hs:DrSmith">
	<rdf:type rdf:resource="hs:Doctor"/>
</rdf:Description>
```

### Identify Violating Triples

List all triples that violate the intended schema constraints.

> [!answer]
> The first `livesIn` is a domain constrait, it cant exist on a visit.
> 
> The first `hasAttendingDoctor` is likely also wrong, unless the doctor is named `City1`
> 
> Alice is most likely not of type `City`, but if she is a city, she cant `hasVisit`ed something as a city.
> 
> The second `hasAttendingDoctor` can only exist on visits, not patients.

### Explain Violations

For each violating triple, identify which schema rule (domain, range, subclass) is violated. Briefly explain why.

> [!answer]
> Domain, range, subclass, domain.
> 
> `livesIn` can't exist on Visits.
> Cities aren't valid doctors for `hasAttendingDoctor`.
> Alice is either a city or a patient, but not both.
> `hasAttendingDoctor` can't exist on patients.

## Knowledge Graph Reasoning

- Symmetry (siblingOf): If siblingOf(x, y), then siblingOf(y, x).
