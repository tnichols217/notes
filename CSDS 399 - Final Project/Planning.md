### 2. Study into "Security by Obscurity"

#### 1. The Fallacy of "Security by Obscurity"

Proprietary vendors argue that hiding code prevents attacks. History proves the opposite: obscurity only stops **friendly** researchers from finding bugs, while sophisticated attackers (state actors/organized crime) reverse-engineer the code anyway. Closed-source creates a "Lag Time" where a vulnerability is known to hackers but hidden from the public until a catastrophe occurs.

- **Key Concept:** _Kerckhoffs’s Principle_—a system should be secure even if everything about it is public.
    

#### 2. Algorithmic Injustice and Lack of Auditability

When code is closed, we cannot verify if a system is biased. This is critical in AI, banking, and the legal system.

- **Example:** If a proprietary "risk assessment" AI denies a loan or suggests a longer prison sentence, neither the victim nor the judge can audit the code to see if it is using "proxies" for race or gender.
    

#### 3. Vendor Lock-In as Economic Coercion

Closed source creates "walled gardens." By using proprietary formats, companies make it prohibitively expensive to switch to a competitor. This results in **Rent-Seeking Behavior**, where companies stop innovating and instead focus on extracting monthly subscription fees from users who have no way to export their own data.

#### 4. Planned Obsolescence and "Bricking"

When a proprietary company goes bankrupt or decides to "end-of-life" a product, the software often stops working. Because the code is secret, the community cannot step in to maintain it. This turns millions of tons of functional hardware into e-waste annually.

#### 5. Surveillance and Hidden Telemetry

Closed-source software is the perfect vehicle for "Surveillance Capitalism." It allows companies to embed data-slurping tools (trackers) that the user cannot see, stop, or delete. Without the ability to compile the software from the source yourself, you can never be 100% sure the "Off" switch for tracking actually works.
